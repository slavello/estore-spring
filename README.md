# E-Store

Приложение для управления деятельностью **сети магазинов электроники**.

Backend на Spring Boot предоставляет REST API (Swagger), данные хранятся в PostgreSQL, веб-интерфейс — минимальная HTML/JS-страница для проверки всех функций.

## Технологический стек

- Язык программирования: Java 11
- Фреймворки: Spring Boot 2.7, Spring Web, Spring Data JPA, Spring Hibernate
- СУБД: PostgreSQL
- Документация API: springdoc-openapi (Swagger UI)
- Frontend: HTML/CSS/JS

## Возможности

* Реестры: **Сотрудники**, **Электротовары**, **Покупки** (CRUD).
* Справочники: **Должности**, **Тип электроники**, **Магазин**, **Тип покупки** (CRUD).
* Постраничный просмотр всех реестров и справочников (`?page=0&size=10`).
* Сортировка реестра покупок по дате покупки (по умолчанию — по убыванию).
* **Проверка наличия товара в магазине**: если товара нет (нет остатка либо товар архивный),
  запись о покупке **не создаётся**, пользователь видит всплывающую подсказку с сообщением.
  Остатки по магазинам хранятся в связующей сущности `shop_stocks`.
* Отчёты:
    * лучшие сотрудники **по каждой должности за последний год** (скользящие 12 месяцев):
        * `criterion=count` — количество проданных товаров;
        * `criterion=sum` — сумма проданных товаров, руб.;
    * лучший **младший продавец-консультант**, продавший больше всех **умных часов**;
    * сумма денежных средств, полученная **через оплату наличными** (по всей сети или по магазину).
* **Импорт данных из zip-архива с CSV-файлами** через веб-приложение.

## Запуск

Сборка и запуск тестов:

```bash
mvn clean package
java -jar target/estore-spring-1.0-SNAPSHOT.jar
```

Запуск проекта:

```bash
java -jar target/estore-spring-1.0-SNAPSHOT.jar
```

- http://localhost:8080/index.html - веб-интерфейс
- http://localhost:8080/swagger-ui.html - Swagger UI

### Импорт из ZIP

Архив содержит CSV-файлы (разделитель `;` или `,`, UTF-8 или Windows-1251, заголовок обязателен).
Имя файла распознаётся по алиасам; примеры файлов — в папке [`sample-data`](sample-data).


Колонка `ID` необязательна. Правила сопоставления:

* справочники сопоставляются **по наименованию** (существующие записи обновляются);
* записи реестров **добавляются**;
* ссылки можно указывать идентификатором строки этого же импорта либо наименованием;
* при импорте покупок выполняется та же проверка наличия: строки без остатка пропускаются
  с ошибкой в отчёте об импорте.

## Допущения реализации

* Одна запись «Покупка» = продажа одной единицы товара.
* Цена продажи не архивируется: отчёты считают сумму по текущей цене товара.
* «Последний год» = скользящий период 12 месяцев от текущей даты/времени.
* Удаление/изменение покупки возвращает товар на склад.
* Backend и frontend разделены: frontend — статические файлы, вся работа с данными только через REST API.
